01 · Overview

速览

这篇论文要回答的问题很具体:在 DeepSeek Sparse Attention(DSA)那类"多头 indexer + Top-K"的稀疏注意力里,能不能不算完所有分数,就确信自己不会漏掉任何一个本该入选的 token?作者的答案是能——只要为每个候选键构造一个严格不低于其真实分数的上界 $U_i$,再用一个严格不高于真实 Top-K 阈值的下界 $\tau$(由种子集合给出)。两者一旦分离($U_i < \tau$),这个 key 就被"证明"不可能进入 Top-K,可以安全丢弃。整个过程中最终选出的 token 与全量打分完全一致,所以论文称之为 lossless(无损)。

02 · Background

背景:稀疏注意力里的"稠密打分"瓶颈

稀疏注意力只让每个 query 去看少数的 key,复杂度看上去是降下来了。但"去看哪几个 key"这一步本身,在 DSA 里由一个有 $H$ 个头的 indexer 完成:每个头算一次 query 与 key 的点积,过 ReLU,再用一个可正可负的权重加权求和,最后取分数最高的 $K$ 个。论文把这件事写成:

$$s_i = \sum_{h=1}^{H} w_h \,[\,q_h^\top k_i\,]_+ , \qquad i \in \Omega \tag{1}$$

其中 $q_h \in \mathbb{R}^D$ 是第 $h$ 个头的 query 向量,$w_h \in \mathbb{R}$ 是它的权重,$k_i$ 是第 $i$ 个 token 的 key。注意两个细节,它们后面会反复出现:一是 ReLU 在加权求和之内(所以是"先整流再带符号求和"),二是权重 $w_h$ 有正有负。正是这两点让"简单地少算几个头"变得不安全——丢掉一个正头会低估分数,丢掉一个负头会高估分数。

于是出现了一个结构性的矛盾:$s_i$ 本身是稀疏使用(只有 $K$ 个 key 最终被真的 attend),但算出 $s_i$ 的过程是稠密的——每个可见 key 都要被所有 $H$ 个头打分一遍。论文用真实模型把这件事量化了出来:

已有的三条加速路线,以及它们共同留下的那道缝

论文把相关工作分成三类,并在每一类里指出"缝"在哪里:

  • 预测/复用式的稀疏选择:NSA 把 token 压缩与细粒度选择结合(Yuan et al., 2025),MoBA 用专家路由做块注意力(Lu et al., 2025),DSA 用学到的多头 indexer 选 token(DeepSeek-AI, 2025);IndexCache 跨层复用索引(Bai et al., 2026),SparDA 预测下一层的选择(Fu et al., 2026),HISA 用层次化块索引 + token 精修(Xu et al., 2026),PIVOT 在 query 组之间共享 proxy 扫描(Liu et al., 2026),MISA 用更少的头筛选用完整 indexer 重排(Zhou et al., 2026)。论文的评价是:这些方法不保证保持原打分器的 Top-K,而且重排无法把已经被排除的 winner 找回来。
  • 精确 GPU 选择与融合打分:Radix selection 用逐位直方图缩小候选(Zhang et al., 2023),GVR 用解码期的时间相关性预测阈值(Cheng et al., 2026),DeepSelect 用有界缓冲区流式处理已物化的分数(Qian et al., 2026),LiteTopK 把全头打分与在线候选过滤融合(Yin et al., 2026)。这些方法加速的是 Top-K 选择本身,但仍然依赖每个 key 的全头分数。
  • 经典文档检索里的分数上界:MaxScore(Turtle & Flood, 1995)与 WAND(Broder et al., 2003)用词项贡献上界 + 运行中的 Top-K 阈值来跳过不必要的文档打分,Block-Max WAND 进一步为每个 posting list 块收紧上界(Ding & Suel, 2011)。论文在这里给出了自己的定位:块级上界必须覆盖块内所有 key,对单个候选往往过松,因而需要更紧的、per-key 的、能利用 query 头几何与激活结构的上界。
把这条缝说清楚:第 1 类方法牺牲了"与原始打分器一致"这个性质来换速度;第 2 类方法保住了正确性但没减少打分本身的工作量;第 3 类方法的原理对,但它的上界形式(块级)在 LLM indexer 这个场景里不够紧。DoSA 要同时拿到"原始打分器的精确 Top-K"与"少算分数",所以必须新造一种上界。这就是论文那句自问自答的由来:Can we avoid full-score computation while certifying that screening discards no winner?
03 · Key Observation

观察:排除一个候选,不需要它的完整分数

论文的出发点是一句朴素但常被忽略的话:"进入 Top-K"是一个可以用反证来否定的事件。要证明某个 key 不可能入选,我们不需要知道它的分数是多少,只需要知道它至多能有多高,并且这个上界已经低于"入选线"。形式化地说,选一个至少有 $K$ 个可见 key 的种子集合 $S \subseteq \Omega$,用原始打分器算出它们的第 $K$ 大分数 $\tau = \tau_K(S)$。因为 $S$ 只是 $\Omega$ 的子集,它的第 $K$ 大分数必然不高于全集的第 $K$ 大分数:

$$\tau_K(S) \le \tau_K(\Omega), \qquad s_i \le U_i < \tau_K(S) \;\Longrightarrow\; i \notin \mathrm{TopK}(\Omega) \tag{2}$$

这给出两个"方向相反"的量:$\tau_K(S)$ 是真实阈值的下界(种子越好越紧),$U_i$ 是 token 分数的上界(证书越紧越好)。两者严格分离,就完成了一次认证式拒绝(certified rejection)。论文同时指出两件工程上很重要的事:差的种子会削弱过滤效果;而额外的精确分数只可能把阈值下界抬高——也就是说,越算越安全,不会因为"多知道一点"反而漏掉 winner。

为什么不能只保留一部分头就了事

最自然的"省钱"办法是只算一部分头。论文用一段话就把这条路堵死了,值得原样理解:丢掉正权重的头是不安全的(会低估分数,把一个本该入选的 key 判死),丢掉负权重的头是安全的但上界会很松(因为负头是往下减的,忽略它们只会把上界抬高)。所以 DoSA 采取的策略不是"丢掉一部分头",而是"直接精确算一部分头,给剩下的头造界"。

具体地,令 $R$ 为 $1 \le r < H$ 个保留头(retained heads)。保留头的贡献被精确算出:

$$S_R(k_i) = \sum_{j \in R} w_j \,[\,q_j^\top k_i\,]_+ \tag{3}$$

剩下的头被分成两组:$P = H_+ \setminus R$(被省略的正头,需上界)与 $N = H_- \setminus R$(被省略的负头,需下界其"减去的量")。保留头 $R$ 怎么选,论文给了一条依赖激活频率的规则(见下一章),但作者强调了一句很关键的话:定理对任意 $R$ 都成立,选择 $R$ 只影响效率与紧度,不影响正确性。这个"正确性与启发式解耦"的设计,是全文可信度的基础。

"边算边收窄"要处理的一个现实问题:阈值必须固定

经典检索里,阈值可以在扫描过程中随已见文档不断抬高(越扫越紧)。DSA 的场景不一样:候选是逐块扫描的,如果阈值在扫描中途变化,前面已经按旧阈值拒绝掉的 key 就无法追回。论文于是选择"固定阈值"——种子集合一旦定下 $\tau$,在整个 screening 与 refinement 阶段都不再改变(算法 1)。这个取舍牺牲了一部分潜在的紧度,换来的是可证明的、与扫描顺序无关的正确性。论文在附录 B.3 里把这个取舍的量写成了一个等式:$\Delta_i > \delta_i + b$ 才拒绝,其中 $b = \tau^* - \tau \ge 0$ 正是"固定阈值带来的亏欠"(阈值下界与真实阈值之间的差距),$\delta_i = U_i - s_i$ 是证书松弛。这个式子把"种子质量"和"证书紧度"两个独立的改进方向,干净地摆在了同一个不等式两边。

这一章的要点:证书的正确性只需要"上界不低、下界不高"这一条不等式,与保留头怎么挑、阈值怎么定无关;而工程上真正难的部分是把这条不等式做成又紧又便宜的上界,以及把"少算"变成"真的省"。前者是下一章(证书),后者是第 ⑤ 章(系统)。
04 · Method

方法:给带符号多头分数造一张"上界证书"

现在面对的是全文最核心的技术问题:给定式 (1) 这种"ReLU 在内、权重有正有负"的分数,如何为每个 key 构造一个便宜而且紧的上界 $U_i \ge s_i$?论文分别处理正头与负头,得到了两个性质不同的工具。

4.1 省略的正头:投影到"已经算过的头"上,再用残差范数兜底

对于每个被省略的正头 $h \in P$,论文在保留头集合 $R$ 里挑一个锚(anchor) $j_h^\star$,把 $q_h$ 分解成"沿锚方向的分量 + 残差":

$$j_h^\star = \arg\max_{j \in R} \frac{[\,q_h^\top q_j\,]_+}{\lVert q_j \rVert_2}, \qquad \beta_h = \frac{[\,q_h^\top q_{j_h^\star}\,]_+}{\lVert q_{j_h^\star} \rVert_2^2}, \qquad d_h = q_h - \beta_h\, q_{j_h^\star} \tag{4}$$

接着用 ReLU 的次可加性、正齐次性与 Cauchy–Schwarz,得到:

$$[\,q_h^\top k_i\,]_+ \le \beta_h\,[\,q_{j_h^\star}^\top k_i\,]_+ + \lVert d_h \rVert_2 \lVert k_i \rVert_2 \tag{5}$$

这个不等式值得停一下,因为它同时解释了"为什么便宜"和"为什么紧":右式第一项复用了一个已经算过的保留头点积(所以投影部分是免费的),第二项只依赖 query 侧的 $d_h$ 和 key 侧的 $\lVert k_i \rVert_2$——而 $\lVert k_i \rVert_2$ 对同一个 key 只算一次,可以跨所有正头共享。换句话说,被省略的正头并没有"消失",它们被折算进了一条残差容差里。

把所有省略正头的贡献汇总,定义折叠权重与总残差容差:

$$\tilde{w}_j = w_j + \sum_{\substack{h \in P \\ j_h^\star = j}} w_h \beta_h , \qquad E_P = \sum_{h \in P} w_h \lVert d_h \rVert_2 \tag{6}$$

于是"保留头 + 省略正头"作为一个整体被 $ \sum_{j \in R} \tilde{w}_j [q_j^\top k_i]_+ + E_P \lVert k_i \rVert_2 $ 兜住。这里有个容易被误读的工程细节:$\tilde{w}_j$ 是折叠权重(folded weights),它只存在于 screening 的这套计划里,不会修改模型参数。若 $P$ 为空(即所有正头都被保留),则 $E_P = 0$、$\tilde{w}_j = w_j$,退化成精确计算。

4.2 为什么"非负投影"是最优的单锚选择

论文在附录 B.1(命题 5)回答了一个自然的问题:锚与 $\beta$ 这么选,是不是最优的?结论是:在所有形如 $[q^\top k]_+ \le \beta [p^\top k]_+ + c\lVert k \rVert_2$ 的单锚上界里,能达到的最小统一容差是 $c^\star = \min_{\beta \ge 0} \lVert q - \beta p \rVert_2$,也就是"$q$ 到 $p$ 生成的非负射线的距离",且式 (4) 的取值恰好达到它。

证明本身很漂亮,值得记一句:若 $q^\top p \le 0$,代入 $k = q/\lVert q \rVert_2$ 会让锚项对所有 $\beta \ge 0$ 都消失,于是 $c \ge \lVert q \rVert_2 = c^\star$;否则令 $d = q - \beta^\star p$,投影满足 $d^\top p = 0$,代入 $k = d / \lVert d \rVert_2$ 同样让锚项消失而左边等于 $\lVert d \rVert_2$,故 $c \ge c^\star$。论文也诚实地划了边界:这优化的是统一范数容差,不是逐点最优的完整上界,也不是保留头集合的最优选择。

还有更紧的两条升级路线(附录 A.1),论文给了但主线用的是前者:
(a) 分组残差(grouped)——把坐标分成 $G$ 组,每组用自己的残差范数 $E_{P,g}$,再用 Minkowski 不等式收成 $\big(\sum_g E_{P,g}^2\big)^{1/2}\lVert k_i \rVert_2$。由 Minkowski 可知它 $\le E_P$,即严格更紧,代价不变(仍然每个 key 一个 RMS 值)。
(b) 联合残差(joint)——利用残差方向之间的相关性,式 (7) 给出 $E_P^{\text{joint}} = \frac{1}{2}\big(\lVert \sum_h u_h \rVert_2 + \sqrt{\sum_{h,\ell} |u_h^\top u_\ell|}\big) \le E_P$,其中 $u_h = w_h d_h$。它的收益来自残差几何,不需要额外的 key 读取,但 query 侧代价是省略正头数的平方级——所以论文把它当作可选 tightening,而不是默认路径。

4.3 省略的负头:用一个"激活模式决定的方向"做聚合

负头这一侧的处理是全文最有意思的设计,也是消融实验证明最关键的一环。负头的贡献是往下减的,所以要构造分数上界,就得给"减去的量"找一个下界。论文选取一个子集 $A \subseteq N$ 做聚合方向:

$$a_A = \sum_{h \in A} |w_h|\, q_h , \qquad L_N(k_i) = [\,a_A^\top k_i\,]_+ \le \sum_{h \in N} |w_h|\,[\,q_h^\top k_i\,]_+ \tag{8}$$

由 ReLU 的次可加性,$L_N$ 不会超过"被省略负头真正减去的量",所以安全。接下来论文问了一个很尖锐的问题:那为什么不干脆把所有负头都放进 $A$?答案是本文一个反直觉但重要的洞见——一个自身不活跃的头(点积为负、过 ReLU 后贡献 0),它的负点积却可以在聚合 ReLU 之前抵消掉其他活跃头的正点积,从而让"减去的量"被低估、上界被放松。所以"多放一个头"并不单调地更好。

DoSA 用种子 key 的激活模式来解决这件事:对采样的种子 key 记录 $M_i = \{h \in N : q_h^\top k_i > 0\}$,$p_h$ 为头 $h$ 的激活频率,取逐分量多数支持:

$$A = \{\, h \in N : p_h \ge 1/2 \,\}$$

论文证明了这是有依据的,而不是拍脑袋:定义可分离代理 $J(A) = \sum_{h \in A} a_h (1 - p_h) + \sum_{h \in N \setminus A} a_h p_h$(其中 $a_h = |w_h|\lVert q_h \rVert_2$),若采样掩码是同一组真实点积的符号,则 $J(A)$ 上界了 $\delta_N(k)/\lVert k \rVert_2$ 的样本均值;而每个头独立地在 $a_h(1-p_h)$ 与 $a_h p_h$ 之间二选一,逐分量多数恰好最小化 $J$,最小值为 $\sum_h a_h \min(p_h, 1-p_h)$。与此同时,前面保留头的挑选规则用同一个 $\min(p_h, 1-p_h)$ 作为优先级,正好把剩余项里最大的一批也拿掉——负头的"选谁保留"和"选谁聚合"是同一个代理目标下的两个决定。

还有一个漂亮的边界情形:如果某个新 key 的活跃集合恰好就是 $A$,那么聚合是精确的(两个松弛项同时为零);其他激活模式仍然安全,只是上界会松一些。频率只影响效率,不影响正确性——这句话值得记住,它意味着激活统计即使有噪声也不会破坏无损性。

4.4 合起来:$U$ 的最终形式,以及每一项的松弛来源

把式 (5)–(8) 合起来,得到本文的分数证书:

$$U_i = \underbrace{\sum_{j \in R} \tilde{w}_j\,[\,q_j^\top k_i\,]_+}_{\text{保留头(放大的权重)}} + \underbrace{E_P \lVert k_i \rVert_2}_{\text{正头残差容差}} - \underbrace{[\,a_A^\top k_i\,]_+}_{\text{负头聚合}} , \qquad s_i \le U_i \tag{9}$$

论文进一步把"这张证书到底松在哪"拆成了三个非负项(附录 B.2,命题 6):

$$U(k) - s(k) = \underbrace{\delta_P(k)}_{\text{正头投影}} \;+\; \underbrace{\sum_{h \in N \setminus A} c_h [x_h]_+}_{\text{漏掉的活跃负头}} \;+\; \underbrace{\min\{Z_A^+(k),\, Z_A^-(k)\}}_{\text{聚合抵消}} \tag{14}$$

其中 $c_h = |w_h|$、$x_h = q_h^\top k$、$Z_A^\pm$ 是聚合头里正负两侧的贡献量。三块的物理含义分别是:(i) 正头被投影近似所付出的代价;(ii) 那些真正活跃、却没被 $A$ 收进去的负头(白白少减了);(iii) 聚合内部正负相互抵消造成的损失。这个分解解释了为什么"负头聚合"是不可替代的:消融实验里去掉它,候选存活率从 2.65% 暴涨到 95.06%(下章详述)——因为它一旦缺席,第 (ii) 项就会把上界抬到几乎无用。

4.5 走查:把论文的配置落到"层号 / 头数 / 张量"上

抽象机制讲完后,值得做一次"配置走查",看看这条公式在真实模型里长什么样。以下数字全部取自论文的正文与附录,标注「整理」的部分是本页依据论文配置做的加总或换算:

05 · GPU Kernel Design

系统:把证书落成 GPU 上的四段流水

证书只保证了"少算",但 GPU 上"少算"未必等于"变快"。论文在开篇就把这个陷阱点破了:认证剪枝减少了算术量,但不规则的幸存者集合会限制 GPU 利用率,还会引入零散的 key 访问。第 ③ 章因此用三个具体的设计决定,把证书翻译成真实的收益。

5.1 设计一:把 query 分组,让筛选走稠密张量核

第一个决定是"分组 + 流水"。

  • 按保留头预算分组:把保留头预算相近的 query 归进固定宽度的 tile,这样只需要少数几个筛选 kernel 就能用稠密张量核 MMA,避免了为每个 query 单独定制宽度带来的碎片化;
  • query 侧只准备一次:保留的 query 行、折叠权重 $\tilde{w}_j$、以及两个 FP8 辅助行,准备一次后跨所有 key tile 复用——这是第 ③ 章反复强调的"query-side quantities are reused across keys"的落地;
  • 阈值在扫描期固定:用种子 key 的精确分数初始化每个 query 的阈值,扫描期间不再变化(与第 ③ 章的固定阈值取舍一致);
  • 生产者/消费者分工:专门的 warp 发异步 key 加载与 MMA,消费者 warp 从 TMEM 累加器里算上界;缓冲的 key tile 让加载与计算重叠。只有 $U_i^{\mathrm{num}} < \tau$ 才拒绝,并用 warp ballot 把幸存决策压成紧凑掩码供 refine 使用。

5.2 设计二:refinement 阶段共享 key 加载

第二个决定针对的是"不规则访问"。如果每个 query 各自 gather 自己选中的 key,那么被多个 query 同时选中的 key 会被反复加载。论文的做法是把幸存掩码压成共享流 + 每 query 流:在一个 4 个 query 的组内,若某个 key 至少通过两个上界、且落在该组共同的可见范围内,就进入共享流(一次加载服务整组的全头打分);其余候选走每 query 流。论文明确承认这是一个取舍——它"用一些额外的 query–key 求值换取更少的 key 搬运"(trades some extra query–key evaluations for fewer key transfers)。这个取舍之所以成立,是因为在长上下文里搬 key 的代价(带宽)往往比多算几次点积更贵,与 Figure 1 里"时间占比高于算术占比"的观察互相印证。每个分数仍然按各自的阈值过滤,所以抽取结果不变。

5.3 设计三:紧凑写回与精确选择

第三个决定针对"写回与选择"。refinement 把全头打分与阈值过滤融合在一起:只有 $s_i^{\mathrm{ref}} \ge \tau$ 的记录才会产生输出。这些记录用紧凑的单调分数编码 + 精确 key ID 存储,从而同时降低 HBM 流量和选择阶段的输入规模。选择阶段的做法是:严格高于边界编码的记录直接保留,恰好落在边界上的候选再用原始分数逐一裁决。这个"边界单独处理"的细节是无损性的必要条件——它保证了定理 1 里"两种过滤器都保留等号"的要求在实现层面真的被遵守。

5.4 解码阶段:换一个思路

Prefill 阶段有大量 query,可以靠 query 分组摊薄证书准备工作。解码阶段每步只有很少的 query,跨 query 组的 key 复用非常有限,同一套收益结构不再成立。论文在这里换了思路保留完整 FP8 打分,转而利用时间一致性:最近若干步里被选中的那些 key 提供了"证人(witness)",用它们在当前 query 上的分数可以给出一个保守的 Top-K 阈值下界;达到或超过这条下界的分数被压紧以供精确选择,同时更新证人集合与选中的索引。所以解码期的收益来源是减少选择工作,而不是减少打分——这解释了 Figure 5 里解码加速(1.06×–1.26×)远小于 prefill 加速的现象。

附带的数值工程(附录 C):证书要在真实硬件上成立,必须把 FP8/FP32 的舍入误差显式地做成容差。论文给出了式 (26) 的形式 $U_i^{\mathrm{num}} = \mathrm{Eval}^{\uparrow}[\alpha_i(\hat{U}_i + \rho_i C) + \varepsilon_{\text{raw}} + \varepsilon_{\text{out}}]$,并强调三点:(1) 必须用向上取整的包络(定向舍入或显式误差界),"round-to-nearest alone is insufficient";(2) 保守的 key RMS 摘要必须满足 $\rho_i \sqrt{D} \ge \lVert \bar{k}_i \rVert_2$,最近舍入的 RMS 不够;(3) 一旦出现非有限值或无法建立覆盖,证书即失效,该 query 保持 flagged 状态,直到走全域恢复(full-domain recovery)——即用原始打分器与选择器把所有可见 key(包括在错误检测之前就被丢弃的那些)重新算一遍。论文特别警告:"从不完整的缓冲区里重新选择"是不够的。这一节读起来像一份工程契约,它划清了"数学上无损"与"在浮点硬件上无损"之间的距离。
06 · Experiments

实验:从微基准到端到端 TTFT

先把实验台子交代清楚,后面的数字才好读。论文在 NVIDIA GPU 上评测 GLM-5.2(32 个 indexer 头)与 DeepSeek-V3.2(64 个头),两者 Top-K 均为 2048;微基准在单卡上跑 GLM-5.2,端到端用 8 路张量并行(TP8),prefill chunk 分别为 32K(GLM-5.2)与 16K(DeepSeek-V3.2)。工作负载取自 InfiniteBench 的英文/中文书籍与代码,补充 Project Gutenberg 与 SQLite 源码以拉长上下文,每个域按 token 化后的长度挑样本,截取 128K 到约 1M token 的连续上下文。基线是 SGLang v0.5.18(全多头打分 + Top-K)与 LiteTopK(把打分、候选过滤与选择融合)。计时用 CUDA events,预热后测量;端到端用 TTFT,并且在请求之间清空 prefix cache。

6.1 Prefill 微基准:60 个配置里全胜,且随长度拉开差距

微基准扫描 128K/256K/512K/768K/1M 五档上下文 × 4K/8K/16K/32K 四档 chunk,共 60 个配置,每个配置重放最后一个 query chunk 覆盖全部 21 个 indexer 层,而且把 query/key 准备工作也算进延迟里(这一点很重要——证书的准备工作是成本,不能藏在计时之外)。

论文还做了一个很具体的敏感性对比,值得单独记下:英文输入、16K query 时,加速比从 128K 的 1.19× 涨到 1M 的 2.58×;而在 1M 处把 query chunk 从 4K 放大到 32K(八倍),加速比只从 2.47× 变到 2.69×。一个变量带来 2.2× 的增长,另一个变量八倍变化只带来约 0.2× 的差异——这干净地把"收益来自 key 维度的稀释"这件事证明了。

6.6 端到端 TTFT:收益随上下文变强

论文用 Amdahl 定律把"为什么增益随长度变强"讲清楚了:设 indexer 时间占比 $f$、indexer 加速 $s$,整体加速为 $S = (1 - f + f/s)^{-1}$。GLM-5.2 的 $f$ 从 128K 的 23.6% 涨到 1M 的 73.0%,DeepSeek-V3.2 在 1M 达到 90.8%。$f$ 越大,加速 indexer 能拿走的请求延迟份额越大。论文也解释了为什么 TTFT 加速(1.86×/1.94×)小于 indexer 加速(最高 2.74×):注意力层与前馈层仍在贡献请求延迟,indexer 不是全部。

实验章的三条结论:(1) DoSA 在全部 60 个微基准配置中最快,且优势随上下文长度单调扩大,说明收益来自削减"长 key 维度"的工作量;(2) 剪枝率 97%+ 且跨语言/模态几乎不变,说明这是分数几何的性质而非数据性质;(3) 消融区分了三种收益——算力(screening)、带宽(sparse writeback)、选择(compact records),其中负头聚合是证书能否成立的命门。

补充:逐层检索速度与一处值得细读的工程披露

附录 D.4 给出了 21 层 × 12 个输入样本 = 252 个格子的逐层检索加速热力图,计时口径是"在准备好的 query/key 上做打分与选择",不含 query/key 准备(与微基准的口径不同,读的时候要注意)。

一处值得单独读的工程披露:候选存储容量修复

附录 D.4 里有一段坦率的"测量范围说明",信息量很大,值得逐点理解:

  • 矩阵保留了原始运行的 247 个格子,在发现候选存储容量问题并修复之后,用三种方法的配对测量替换了 5 个格子:EN01 的第 26 层,以及 EN02、EN04、ZH04、CD04 的第 1 层;
  • 修复保持了打分与选择规则、四锚初始化与 16K 的内部 query scratch 不变;在约 1M key 的容量下,它为每个 query 预留 1,024 个候选 ID 页与 114,688 条输出记录,相对原始分配增加了 9.94 GiB 的工作区;
  • 论文明确声明:修复之后没有重跑完整矩阵。

这段披露与附录 C.3 的理论警告是同一个问题在实测中的现身:C.3 早就指出"缓冲区容量 $C_{\text{buf}}$ 并不限制有多少 key 满足 $U_i \ge \tau$——如果所有分数都等于 $\tau$,即使界是精确的,每个 key 都会通过",并强调"丢弃溢出的候选会丢失必需的 Top-K ID"。也就是说,这次容量修复不是调参,而是在修一个正确性问题。而它同时暴露了这套方法的真实空间代价:约 1M key 时额外 9.94 GiB 工作区(附录未给出该数值占单卡显存的比例,故本页不做推算)。这两点合起来,是评估 DoSA 能否上生产时最该追的两条线索。

另外两个容易被略过但重要的口径细节:(1) Figure 1 的 profiling 是在 DoSA 与 LiteTopK 都禁用的情况下做的(用真实模型权重与文本),所以它刻画的是"原始 indexer 的代价",不是 DoSA 的代价;(2) 附录 D.1 明确说明 indexer 区间包含 query/key 准备、key-cache 访问、打分与选择,分母是完整的模型 prefill GPU 区间,排除了 CPU 分词与请求传输,并且与 TTFT 是不同的量——论文特意做了这个区分,避免了用 GPU 占比去解释端到端延迟的常见混淆。此外 D.1 说明 1K = 1,024 token、375K = 384,000 token、约 1M = 1,048,569 token,并声明 DeepSeek 超出其声明上下文支持的测量"只支持计算伸缩性观察,不构成任务精度的结论"。
这一章的要点:逐层热力图把"平均很快"拆成了"逐格可靠",并诚实地留下了三个落后格子;而候选存储那 5 个格子的重测,是全文最值得注意的工程信号——它说明证书的正确性在真实系统里会以"内存容量"的形式重新出现,而这部分代价论文没有完全量化。
08 · Commentary

点评:定位、边界与值得追问的地方

8.1 这篇论文真正做对了什么

第一,问题选得准。稀疏注意力的"省"和"选"之间有一道长期被默认接受的税:为了省下 99% 的 attention 计算,必须先花掉一次稠密打分。论文用 Figure 1 把这笔税量化成了 73.0%/90.8% 的时间占比,并指出它与 47.4%/83.2% 的算术占比之间的落差——"时间比算术更贵"这个观察直接决定了后面两章的设计(不但要少算,还要少写、少选)。这不是一个先有方法再补动机的叙事。

第二,把"无损"做成了可验证的强性质,而不是模糊的"近似"。Theorem 1 的陈述方式值得学:它明确区分了"给定公共全序时返回完全相同的 Top-K"与"未规定全序时返回一个合法的 Top-K 集合",并且明确说明"有效的并列 Top-K 集合不必然产生相同的生成文本"。同时 Algorithm 1 里两处过滤器都保留等号($U_i \ge \tau$ 保留、$s_i \ge \tau$ 保留),这个细节在实现里很容易写错,论文把它写进了算法而不是留给读者猜。附录 C 进一步把"实数的无损"与"FP8 上的无损"分开处理,给出了必须向上取整、必须保守 RMS、必须全域恢复的清单——这是把正确性主张从数学层延伸到硬件层的负责任做法。

第三,正确性与启发式被干净地解耦。论文反复强调:$R$ 的选取、$A$ 的选取、$p_h$ 的估计都不影响正确性,只影响效率("The proof holds for any R"; "The frequencies guide efficiency, not correctness")。这个设计的意义在于:任何针对特定硬件或模型的调优都不会破坏无损性。相比之下,MISA 那类"用更少头筛选 + 全 indexer 重排"的方案,无论重排做得多好,都不可能把已被排除的 winner 找回来——论文用一句话点出了这个不可逆性,是全文对相关工作最有力的一次区分。

第四,消融实验回答了"为什么有效",而不只是"有效"。Figure 9 的 No-neg.-aggregate 变体(存活率 2.65% → 95.06%,延迟 9.507×)是一个信息量极高的负结果:它把"证书的三项松弛里哪一项是主导"从理论(命题 6)坐实到了数字上。而 All-neg.-support 变体(存活率升到 4.06%、延迟 +12.0%)则验证了"不能把负头全塞进聚合"这个反直觉洞见——这条结论在工程上是可操作的:激活频率统计是必要的,且它只花一次采样成本。

8.3 论文自述的局限

  • 仍然要扫描每个 key:"DoSA still scans every key"——省的是每键的全头打分,不是扫描本身。所以证书的准备工作如果摊不薄,短上下文就会得不偿失;
  • 短上下文或松界下可能入不敷出:"short contexts or loose bounds can leave insufficient savings to offset screening";
  • 需要保守评估:数值保证要求相对原始打分器做保守评估;有效的并列 Top-K 集合不必然产生相同的生成文本;
  • 只证明了计算收益,没有证明任务精度:"The measurements establish computational benefits, not improved task accuracy beyond a model's trained context."

8.4 未披露、值得补测的点

以下几条是本页在通读后的追问,与上面的"自述局限"分开列:

  • 候选缓冲的显存账本:附录 D.4 披露容量修复带来 9.94 GiB 额外工作区(约 1M key),但未见披露它在实测卡型上的显存占比、以及对可服务并发数/最大上下文的影响。考虑到这关系到能否上生产,值得补一组"不同 $C_{\text{buf}}$ 下的显存–延迟曲线",尤其是候选池被填满而触发恢复(full-domain recovery)的频率——论文只在 Figure 9 提到计时"包含恢复开销",未给出触发率。
  • 尾延迟与最坏情况:论文报的是加速比(中位数/几何平均口径),未见披露 p99 延迟与"最坏层/最坏输入"的表现。既然 Figure 6 显示第 1 层剪枝率只有 89%–93%(其余层 >95%),而附录 D.4 又说明第 1 层有 4 个格子被重测,那么浅层就是这个系统的尾部风险所在,值得单独给一组分布而非均值。
  • 激活统计的采集成本与漂移:多数支持 $A$ 依赖种子 key 的激活频率 $p_h$。论文说明频率只影响效率不影响正确性,但未见披露采样多少 key 才能稳定、在线更新 $A$ 的频率与开销、以及跨域切换时是否需要重采。如果 $A$ 对分布漂移敏感,那么"按域调参"的隐藏成本可能被低估。
  • 头预算 $r$ 与 $d_a$ 的联合调优:论文给了式 (21) 的判据(多一个头只在它避免足够多的全量重打分时才划算),并说明 32 头实现里 $r = 14,16$ 走绝对值形式、$r = 20$ 走基形式;但未见披露这三个路径各自的实测加速与存活率对照表。既然 $r$ 是直接决定 $r + d_a$(每键筛选行数)的旋钮,这张表对复现和调优都很关键。
  • 独立复现与跨框架一致性:评测建立在作者自家的 kernel(flash-indexer)与 SGLang/LiteTopK 的对比上;未见第三方在别的推理栈(如 vLLM、TensorRT-LLM)或别的稀疏注意力变体上的复现。此外数值条件(式 26–28)依赖向上取整的包络与保守 RMS,这类实现的正确性很难从论文文本直接验证,值得补一组"故意注入舍入误差后仍不丢 winner"的压力测试。
  • 与"近似但要更快"的方法的正面对比:论文的定位是无损,因此与 MISA 等方法的对比是性质层面的(不保证原 Top-K),而非端到端速度的正面对撞。对于只关心任务精度、不要求 bit-exact 选择的使用者,"无损 vs 近似"在同等精度下的速度差是多少,是一个有价值但论文未回答的问题。

8.5 一句话评价

这是一篇把"正确性论证"和"系统实现"都做实了的优化类论文:它的核心思想(用上界 + 下界分离来认证拒绝)并不新鲜,新鲜且困难的是为 LLM 里那个带符号 ReLU 的多头打分函数造出一张又紧又便宜的 per-key 证书——正的用投影复用已算过的头,负的用激活多数方向聚合成一行,再用命题 6 把松弛拆成可归因的三块。它对自己边界的交代(仍然扫每个 key、短上下文可能不划算、只证计算不证精度、候选容量修复未重跑全矩阵)也足够坦率。真正决定它能否从"论文加速比"走向"生产收益"的,恐怕不是那张证书的数学,而是附录 D.4 里那 9.94 GiB 工作区:无损之所以比近似贵,往往就贵在这些不体现在 FLOPs 里的地方。
