Category 01

🎯 注意力与 KV Cache 🎯 Attention & KV Cache

一层里「哪些 key 被看到」由谁决定。八篇按决策权排列:结构/位置 → 复用已有选择 → 复用模型自己的 Summary → 层内内容打分 → 层内学习路由 → 模型自己声明 → 不需要信号;DoSA 是这一叠里的一个例外——它不改变谁被看到,只改变"筛选"这件事要花多少算力,用一张可证明不丢 winner 的分数上界把选择本身变成条件计算。 Who decides which keys a layer sees. The eight papers run from external structure to the model itself, and finally to a deliberate refusal to decide: position/structure → reuse of an existing choice → reuse of the model's own Summaries → in-layer content scoring → an in-layer learned router → the model's own declaration → no signal at all. DoSA is the exception in this stack — it does not change who is seen, only what the screening costs, turning selection itself into conditional computation via a score upper bound that provably discards no winner.

稀疏注意力 · 结构化窗口 · GQA · 张量并行Sparse Attention · Structured Windows · GQA · Tensor Parallelism

① CoWindow Attention
完整因果覆盖是 head 集合的集体属性 ① CoWindow Attention
Full Causal Coverage Is a Collective Property

所有 KV head 共享近邻窗与前缀 sink 窗,剩余长程距离均分成互补区间、每 head 一段——单个 head 对远处稀疏,合起来对整条因果前缀稠密。不带路由器也不带索引器(选择开销 O(1)、辅助状态 O(H_k)),按全局 KV-head 编号对齐张量并行。8K 覆盖消融上 100% 覆盖拿到 89.73%(重复窗仅 21.32%),128K 算子级前向 7.4× / 反向 8.6×,14B 训 32K 时总训练 FLOPs 降 28.5%。 All KV heads share a near window and a prefix-sink window while the remaining long-range distances are split into complementary intervals, one per head — individually sparse at distance, collectively dense over the causal prefix. No router, no indexer (selection cost O(1), auxiliary state O(H_k)), with windows assigned by global KV-head index to align with tensor parallelism. 100% coverage reaches 89.73% on the 8K ablation (duplicated windows: 21.32%); at 128K the operator runs 7.4× faster forward and 8.6× backward, with 28.5% fewer total training FLOPs at 14B/32K.

块稀疏注意力 · 金字塔 Top-K · LogSumExp · O(N log N)Block Sparse · Pyramid Top-K · LogSumExp · O(N log N)

③ PISA
对数线性的块稀疏注意力选择 ③ PISA
Block Sparse Attention with Log-Linear Complexity

块稀疏注意力省下了注意力计算,却没省下"挑哪些块"——为每个 query 扫全部 N/C 个键块,选择阶段仍是 O(N²/C)。PISA 把键池化成 O(log N) 层金字塔,从最粗层逐层 Top-K 展开,块分数改用子块摘要上的 LogSumExp 并用 Jensen 不等式给出夹逼论证。256K 选块延迟比 BSA 快 9.95×,Recall@8 90.95% 对 BSA 的 85.91%;RULER 平均 62.80 对 BSA 的 54.99。16K 以内 BSA 更快,交叉点在 16K–32K 之间。 Block-sparse attention saves the attention compute but not the cost of choosing blocks — scanning all N/C key blocks per query keeps selection at O(N²/C). PISA pools keys into an O(log N)-level pyramid, narrows Top-K level by level from the coarsest, and scores blocks with a LogSumExp over child summaries backed by a Jensen sandwich argument. Selection latency is 9.95× faster than BSA at 256K, Recall@8 is 90.95% against BSA's 85.91%, and the RULER average is 62.80 against 54.99. BSA is still faster below 16K; the crossover sits between 16K and 32K.

DSA Indexer · Top-K 选择 · 上界证书 · 无损剪枝 · GPU KernelDSA Indexer · Top-K Selection · Upper-Bound Certificate · Lossless Pruning · GPU Kernel

⑦ DoSA
让"找 Top-K"这件事变成本身可以跳过的计算 ⑦ DoSA
Making "find the Top-K" a computation that can itself be skipped

稀疏注意力只访问少数 key,但"找出这些 key"仍要对每个 key 打全部头的分。DoSA 的核心观察是:Top-K 选择只需要排除候选的充分证据,不需要它的完整分数。于是构造一个严格不低于真实分数的上界 Ui,配一个由种子集合给出的阈值下界 τ——两者一旦分离就认证式拒绝该 key,最终选出的 token 与全量打分完全一致(无损)。难点在于打分函数带 ReLU 且头权重有正有负:正头投影到已算过的头上、负头按激活多数聚合成一行。Indexer 最高 2.74× / 1.69×,1M 上下文 TTFT 1.86× / 1.94×,剪枝率 97.2%–97.5%。 Sparse attention visits few keys, yet finding them still scores every key with every indexer head. DoSA's observation: Top-K selection needs sufficient evidence to reject a candidate, not that candidate's full score. Build an upper bound Ui that is never below the true score, pair it with a threshold lower bound τ from a seed set — once they separate, the key is certifiably rejected, and the final token set is identical to full scoring (lossless). The hard part is a signed ReLU scorer: positive heads are projected onto already-computed heads, negative heads aggregated into one row by activation majority. Indexer up to 2.74× / 1.69×, TTFT 1.86× / 1.94× at 1M context, 97.2%–97.5% pruning.

⑧ KSA V2
同一套 Summary,既当压缩记忆又当稀疏索引 ⑧ KSA V2
One Summary Hierarchy, Both Memory and Index

在 KSA 的 3:1 混合里,每个 chunk 的 Summary 每层都被算出来、逐层精修,却只当"低分辨率记忆"用。KSA V2 让它演两个角色:作为记忆,在存储时把每 km 个连续 Summary KV 池化成层私有的 Meta 条目,远端压缩率从 ks=8 提到 1024,而层间流动的 Summary 表示完全不动(C-KSA);作为索引,拿它当路由查询给每个 b-token 块打分,原来读全部因果 KV 的 Full 层只读 sink + 选中块 + 局部窗口(S-KSA)。两者都不增 token、不改布局,可直接 retrofit。1.9B/128K 下常驻缓存 −40.4%、prefill 1.51×、decode 1.27×,RULER 均值只从 72.61 掉到 72.39。 In KSA's 3:1 hybrid, each chunk's Summary is computed and refined every layer yet used only as low-resolution memory.
